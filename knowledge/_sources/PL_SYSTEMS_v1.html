PL-SYS-2025-001 // REV.1 PARADISE LOBBY — SYSTEM CLASSIFICATION NOT FOR DAILY USE — REFERENCE ONLY
Purpose
This document defines the three system classifications used to evaluate Paradise Lobby output. Systems A and B define what the project is not. System C defines what it is. The classification is a content and tone filter — it is applied during building and again at the anchor test before export.
When a document feels wrong during production and you cannot identify why, it is almost always because one element has drifted into System A or System B. This document gives you the vocabulary to find it.
The core principle — stated once, never repeated
Foundation
The institution processes things it cannot classify. The documents are the residue of that processing — not the record of it, not the announcement of it. The institution does not know you have these pages. The institution may not fully understand what it processed.
Three systems — summary
System AEVENT — the document creates or announces something. Points forward in time. Something is happening or will happen.
System BRECORD — the document describes something that happened. Points backward. A coherent reconstruction of events is possible from the content.
System CRESIDUE — the document is the administrative trace of a process. Points nowhere. Reconstruction fails. The institution processed something it could not resolve.
Which system Paradise Lobby operates in
R-SYS-01Paradise Lobby operates exclusively in System C. Always.
R-SYS-02Systems A and B are defined so you can recognise drift, not because you will intentionally use them.
R-SYS-03A single line of System A or B content in an otherwise correct document invalidates the document. Find it and remove it.
The drift detection check — run this when something feels wrong
Does any part of the document announce, invite, or point toward a future event or outcome?
YES → SYSTEM A
Remove it.
Can a viewer reconstruct a coherent sequence of events from the document's content — even partially?
YES → SYSTEM B
Remove it.
Are the viewer's questions multiplying rather than resolving as they read the document?
YES → SYSTEM C
Correct.

PL-SYS-2025-001 // REV.1 SYSTEM A — EVENT NOT FOR DAILY USE
SYS A
Event
BANNED — DO NOT PRODUCE
A document that creates or announces something. It points forward in time. The viewer is being informed that something is happening or will happen. The institution has a role to play — it is acting, communicating, inviting.
What System A feels like
Anticipation. Something is coming. The document exists to prepare the viewer for an event. The institution is performing — it wants to be seen doing something.
Real-world examples of System A
Concert poster. Press release. Product launch. Invitation. Campaign announcement. Any document whose purpose is to cause something to happen in the future.
System A contamination in bureaucratic forms — what to watch for
Timelines"Assessment will be completed within 30 days." — This promises a future outcome. System A.
Commitments"A full review will follow." — This commits the institution to a future action. System A.
Invitations"You are requested to attend." — This addresses the viewer and involves them in an event. System A.
We will languageAny sentence beginning with "We will…" or "The institution will…" — System A.
Announcements"Notice of Documentation: the submitted image has been accepted for review." — This announces an outcome. System A.
Examples — same subject, System A vs System C
SYSTEM A — wrong
NOTICE OF DOCUMENTATION
The submitted image has been accepted for review. A full assessment will be completed within 30 days. You will be notified of the outcome.
SYSTEM C — correct

CASE NO. PL-25-0001
DATE [blank]
STATUS PENDING REVIEW
HANDLER [blank]
Why Paradise Lobby avoids System A
System A requires a narrative — a before and an after. It gives the viewer a role: witness to something about to happen. The institution performs for the viewer. Paradise Lobby's institution does not perform. It processes cases without awareness of being observed, without communicating to an outside audience, without building toward events. An institution that announces things is comprehensible. Paradise Lobby's institution is not.

PL-SYS-2025-001 // REV.1 SYSTEM B — RECORD NOT FOR DAILY USE
SYS B
Record
BANNED — DO NOT PRODUCE
A document that describes something that happened. It points backward in time. A coherent reconstruction of events is possible from reading it. The viewer can understand what occurred — even if the document is bureaucratic in form.
What System B feels like
Understanding. You know what happened. The document explains, even if technically it is a form. The institution is coherent — it received something, logged it, described it, and filed it. A story is recoverable from the content.
Real-world examples of System B
News article. Police report that reads as narrative. Incident report with clear sequence of events. Medical record with complete symptoms and treatment. Court filing with reconstructable timeline. Any document where the content, taken as a whole, explains something.
The System B discriminator — one test only
System B test
Can a reader reconstruct what happened from this document — even partially? If yes: System B. Remove the explanatory content. Replace with [BLANK], [REDACTED], or PENDING.
System B contamination — what to watch for
Narrative description"At 02:14, an image depicting an unmanned corridor was submitted via intake channel B-17." — This tells a story with a time, an action, and a subject. System B.
Complete subject identification"The subject showed no identifiable personnel." — This describes what the exhibit contains. Now the viewer knows what the image is. System B.
Causal explanation"Access was denied due to incomplete classification data." — This explains why something happened. System B.
Resolved fieldsAll fields filled in correctly, no blanks, coherent data throughout. The document is complete. System B.
Sequential logicFields that, read in order, construct a timeline or narrative. Even if each field individually seems neutral. System B.

Why Paradise Lobby avoids System B
System B still gives the viewer resolution. Even in bureaucratic form — even with stamps and case numbers — if the content explains, the institution becomes legible. The viewer understands the institution. That is the wrong outcome. Paradise Lobby's institution must remain fundamentally incomprehensible — not mysterious for dramatic effect, but incomprehensible because it genuinely cannot classify what it is processing.
A key distinction: a police report that is incomplete, contradictory, and missing key fields can be System C even though it resembles a System B document. The discriminator is not the form — it is whether reconstruction succeeds. System B = reconstruction possible. System C = reconstruction fails.

PL-SYS-2025-001 // REV.1 SYSTEM C — RESIDUE NOT FOR DAILY USE
SYS C
Residue
PARADISE LOBBY — ALL OUTPUT
A document that exists as the administrative trace of a process the institution could not resolve. No event. No story. No resolution. The institution processed something it could not classify and filed the result. The viewer arrives after everything has already happened and finds only the paperwork. The paperwork does not explain what happened.
Core principle — System C
The institution processes things it cannot classify. The blanks are not bureaucratic laziness — they are evidence of institutional incomprehension. The handler field is blank not because the clerk forgot, but because the institution could not determine who should handle this. The date is missing not because it was overlooked, but because the intake timestamp was never confirmed. Every incomplete field implies that the institution tried and could not answer.
What System C feels like
You are holding something you were not supposed to find. The institution processed this without understanding it. The institution does not know you have these pages. The case is open, suspended, unresolved — not because something dramatic is pending, but because the institution's process reached an incomprehensible input and stalled.
Three rules that define System C
R-C-01No drama. A SEIZURE ORDER ACTIVE stamp is not dramatic — it is procedural. The institution issues seizure orders the way it issues any administrative action. Without emphasis. Without urgency.
R-C-02No event creation. Nothing in the document announces that something is about to happen. The institution does not build toward events. Administrative status fields (PENDING, ON HOLD, SUSPENDED) are allowed — they imply indefinite continuation, not a future action.
R-C-03Only processing residue. Everything in the document is the result of a process that has already occurred or is indefinitely suspended. The case is open. The review is pending. The archive priority is unassigned. The institution is not waiting to act — it simply has not resolved anything and may never do so.
Real-world examples of System C
A form with half its fields blank. An intake sheet for something that was logged but never resolved. A chain of custody record where one transfer has no destination. A classification document where the classification field reads PENDING. A photocopy of a photocopy of a report that no longer exists in original form. A denial notice that does not state what was denied.
System C in Paradise Lobby — specific examples
C1 correctIntake sheet. Grey exhibit image. Two blank fields. Stamp: RECEIVED — UNCLASSIFIED. Footer OCR string. No explanation of what was received or why.
D1 correctWord BREACH at SCALE_A. Case reference. Date field blank. Stamp: HOLD — REVIEW PENDING. What was breached is not stated anywhere in the document.
C2 correctChain of custody table. Third transfer row: recipient field blank. The document travelled somewhere. Nobody recorded where. The table does not resolve.
D2 correctBoxed directive: ACCESS TO THIS RECORD HAS BEEN SUSPENDED. No reason given. No duration stated. No reference to what the record contains.

Kill-switch — apply during production when drift is detected
If any line in the document explains what happened or why, delete that line and replace it with [BLANK], [REDACTED], or PENDING. One sentence of explanation collapses a System C document into System B. There are no exceptions.

The clerk artifact — mandatory System C marker
Every CUSTODY document must include one clerk artifact — evidence that a human processed this form and made an error. Not damage aesthetic. Proof of process.
Mis-typed fieldType CLASSIFCATION, cover with VOID_WHITE bar, type CLASSIFICATION correctly beside it. The correction shows the institution tried. The error shows the clerk was human.
Crossed-out valueA field value struck through and replaced — HANDLER: [strikethrough] P. VAAN → J. MARSH. The case changed hands and someone updated the form by hand.
Wrong form numberFooter reference says ATT-02 but the document is clearly ATT-01. Nobody corrected it.
One clerk artifact per CUSTODY document. Logged in the session log. Do not repeat the same artifact in consecutive sessions.
Quick reference — production use
IN BUILDAfter placing every content element: is this explaining, announcing, or resolving something? If yes — remove it.
AT ANCHOR 2Temperature check. Administratively cold, not stylishly cold. System C is the temperature of a filing cabinet nobody has opened in three years.
AT ANCHOR 4Run kill-switch. Find the line that explains. Delete it. Replace with [REDACTED] or PENDING.

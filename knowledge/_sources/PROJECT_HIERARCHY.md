# PROJECT HIERARCHY

Status: Active v1.0  
Purpose: Define which project documents are binding, which are strategic, and how conflicts are resolved.

---

## 1. Core rule

Not every project document has equal authority.

Stranger Than Paradise / Paradise Lobby only stays coherent if the documents are read in order of authority.
If two documents conflict, the higher layer wins.
No silent drift.
No private reinterpretation.
No accidental overruling through convenience.

---

## 2. Authority layers

### LAYER 1 — WORLD AUTHORITY (highest)
These define the world itself.

- `STP_WORLD_RULES.txt`
- `GRAPHIC_DESIGN_EXTRA_CONTEXT.md` or latest approved replacement

These documents define:
- what the project fundamentally is
- what Paradise Lobby is and is not
- the archive / evidence / artifact order
- anti-drift behavior
- protected areas and ongoing system assumptions

If any lower document conflicts with Layer 1, Layer 1 wins.

---

### LAYER 2 — CANON + OPERATIONS AUTHORITY
These define how Paradise Lobby canon is built and judged.

- `PL_SYSTEMS_v1.html`
- `PL_OPS_v3.html`
- `PL_BUILD_GUIDE_v2.html`
- `PL_TRAINING_v3.html`
- `PL_CANON_RULES.md`

These documents define:
- System C behavior
- case logic
- build order
- template behavior
- type roles
- damage logic
- carousel/export logic for canonical releases

If any Layer 3 document conflicts with Layer 2, Layer 2 wins.

---

### LAYER 3 — COMMERCIAL + PUBLIC STRATEGY AUTHORITY
These define how the world is distributed, translated, and monetized.

- `PERSONAL_BRAND_POSITIONING.md`
- `PUBLIC_CONTENT_SYSTEM.md`
- `CLIENT_TRANSLATION.md`

These documents define:
- public identity
- growth strategy
- portfolio logic
- Instagram/public dossier behavior
- client-facing translation
- offer structure

Layer 3 can extend the system.
Layer 3 cannot rewrite canon.
Layer 3 cannot contradict world authority.

---

## 3. Binding reading order

When making work, use this order:

1. `STP_WORLD_RULES.txt`
2. `GRAPHIC_DESIGN_EXTRA_CONTEXT.md` or latest approved replacement
3. `PL_CANON_RULES.md`
4. `PL_SYSTEMS_v1.html`
5. `PL_OPS_v3.html`
6. `PL_BUILD_GUIDE_v2.html`
7. `PL_TRAINING_v3.html`
8. `PUBLIC_CONTENT_SYSTEM.md`
9. `CLIENT_TRANSLATION.md`
10. `PERSONAL_BRAND_POSITIONING.md`

For canon output, stop at Layer 2 unless a public release decision is being made.
For client/public work, apply Layer 3 only after Layer 1 and 2 are understood.

---

## 4. Conflict resolution rules

### Rule A — World over strategy
If a strategic or commercial idea weakens the world, the idea loses.

### Rule B — Canon over content convenience
If a public content tactic forces Paradise Lobby canon into something false, the tactic loses.

### Rule C — Distribution container is not the same as the canonical piece
A canonical piece remains a single resolved canonical surface.
A carousel, reel sequence, or dossier post is a public distribution container.
This distinction allows Instagram-native releases without breaking the "one system per piece" rule.

### Rule D — Client work is translation, not canon by default
Client work may use the pressure of the world without becoming literal Paradise Lobby canon.

### Rule E — Version bump required
If a conflict cannot be solved by the hierarchy above, the relevant document must be revised and version-bumped.
No silent reinterpretation.

## 5. Active interpretations

The following interpretations are now binding:

### A. Document-first does not mean print-only
Paradise Lobby remains document-first in logic.
That logic may resolve as:
- a physical print
- a Photoshop-built print study
- a digital poster surface
- a document-derived motion frame
- a dossier release built from one or more canonical surfaces

The governing principle is document behavior, not only paper size.

### B. Physical output is part of the core, not an optional afterthought
Scanned prints, damaged print studies, wall proofs, folded copies, and tactile insert material are fully valid parts of the system.

### C. JetBrains Mono is not the Paradise Lobby canon type stack
JetBrains Mono may be used in:
- website/interface work
- non-canonical system notes
- auxiliary STP environments
- public-facing non-canonical layouts where appropriate

Paradise Lobby canon remains governed by the fixed bureaucratic / machine / directive stack defined in Layer 2 documents.

### D. Public carousel logic is allowed
A public dossier carousel may combine source, process, motion, artifact, and canonical surfaces.
That does not mean multiple systems are blending inside one canonical piece.
It means the public release is sequencing different materials around a case.

## 6. What must stay strict

These things are non-negotiable unless formally revised:
- Paradise Lobby is not the event
- System C remains the canonical mode
- L2 must dominate in canon
- machine logic must appear in canon
- kill-switch remains absolute
- friction / proof remains mandatory
- if it looks designed, remove one element
- public growth cannot overrule canon logic

---

## 7. What is allowed to evolve

These may evolve with version bumps:
- personal brand wording
- public content ratios
- service packaging
- client-facing language
- dossier/carousel grammar
- case-study structure
- print/product release packaging

These are strategic layers, not metaphysical laws.

---

## 8. Working principle

The project should now be understood as:

- **STP** = world container
- **Paradise Lobby** = strict canonical processing layer
- **public content** = dossier-based distribution layer
- **personal brand** = commercial front door
- **client translation** = monetizable application layer

That is the correct architecture.

## Core rule

Sell translated outcomes, not internal mythology.

Clients buy:
- release-ready visual systems
- rollout assets
- motion and print extensions
- strong art direction under constraint

Clients do not need:
- Paradise Lobby doctrine
- System C jargon
- internal archive language as lead framing

---

## Commercial intake

Use this intake before scope, fit, or quoting.

Required intake fields:
- client name
- brand / project name
- contact role
- sector
- objective
- primary deliverable need
- launch or delivery date
- known formats needed
- source materials available
- approval decision-maker
- budget range
- usage scope
- whether the work is internal, public campaign, or retail/product-facing

If any of the following are unknown, mark quote status `HOLD - INTAKE INCOMPLETE`:
- objective
- deliverables
- deadline
- budget range
- usage scope

Do not produce a firm quote while those are missing.

## Fit check

Classify every lead as one of three outcomes.

| Fit | Meaning | Action |
|---|---|---|
| Strong fit | The project benefits from a controlled visual world, sequence logic, typography pressure, motion, print, or artifact logic | Proceed to scoping |
| Medium fit | Some system strengths apply, but the brief needs more translation and less canonical pressure | Proceed with constraints |
| Weak fit | The project needs generic, soft, trend-led, or low-authorship output | Decline or redirect |

Strong-fit categories:
- musicians and labels
- culture-led fashion
- editorial or publishing
- exhibitions and screenings
- art-direction-heavy launches
- product or campaign rollouts needing a harder visual world

Weak-fit categories:
- generic corporate communication
- soft wellness branding
- low-differentiation social content retainers
- briefs requiring literal imitation of another brand
- projects that ban experimentation while demanding originality

Rule: do not bend the system to win weak-fit work.

## Offer ladder

All offers should map to translated outcomes already supported by the public system.

| Offer | Use when | Typical output |
|---|---|---|
| Release World System | A project needs a full visual direction and rollout language | Posters, motion, rollout assets, optional print study |
| Motion Poster Pack | A project mainly needs moving hero assets | 1-3 motion-led hero assets plus cutdowns |
| Poster Series | A project needs still-based key art under one system | 2-4 posters or key visuals |
| Dossier Rollout | A project needs sequenced launch communication | Carousel structure, crops, motion/stills, detail assets |
| Print Study / Artifact Add-On | A project benefits from material proof and tactile credibility | Print studies, scans, labels, inserts, edition fragments |

Do not invent a custom package first.
Start from the nearest offer and adjust only where needed.

## Scope construction

Build scope in this order:
1. define the core outcome
2. define the minimum asset set needed for that outcome
3. define the formats
4. define the review rounds
5. define the license
6. define optional add-ons

Scope must name:
- final deliverables
- working formats
- number of distinct directions
- review rounds included
- delivery milestone(s)
- what source material the client must supply
- what is explicitly not included

If an item is not listed, it is not included.

## Pricing logic

Pricing is built from structure, not improvisation.

Every quote has four parts:
1. creative direction fee
2. production fee
3. usage / licensing fee when applicable
4. add-ons

Price drivers:
- number of distinct directions
- number of final assets
- motion complexity
- print or physical proof requirements
- source generation / sourcing complexity
- speed / rush constraints
- usage scope
- approval complexity

Do not price by hours alone.
Use hours internally for risk estimation, not as the public value story.

## Quote statuses

Use one status per lead.

| Status | Meaning |
|---|---|
| `INTAKE` | Information gathering only |
| `HOLD - INTAKE INCOMPLETE` | Cannot scope yet |
| `FIT REVIEW` | Intake complete, fit decision pending |
| `SCOPE DRAFTED` | Offer and deliverables defined |
| `QUOTE ISSUED` | Formal quote sent |
| `ON HOLD` | Client paused |
| `DECLINED` | Not proceeding |
| `BOOKED` | Quote accepted and scheduled |

## Revision policy

Revision control protects quality and margin.

Default rule:
- 1 direction selection round
- 2 revision rounds on the selected direction
- final production polish only after revision round 2

Revision round means one bundled feedback pass from one decision-maker.
Fragmented feedback from multiple people is not multiple free rounds.

Out-of-scope revision triggers:
- new direction after approval
- additional deliverables not listed in scope
- changed usage territory or duration
- changed launch date creating rush conditions
- additional stakeholder rounds
- request to make the work generic after approving a differentiated direction

When out of scope, issue a change order before continuing.

## Licensing / usage rights

Usage must be stated in writing.
Do not leave rights implied.

Minimum license fields:
- licensee
- asset set covered
- usage type
- channels
- territory
- duration
- exclusivity yes/no
- right to adapt yes/no

Typical usage types:
- organic social
- digital campaign
- editorial / publishing
- event / exhibition
- print retail
- physical edition / product
- paid advertising

Default rule:
- internal working files are not transferred unless explicitly priced
- source prompts, raw generations, and process debris are not transferred by default
- editable production files are licensed separately from flat exports

If the client requests broad perpetual exclusive rights, price that as a licensing increase, not as a free default.

## Add-ons

Use add-ons to extend a clean base scope.

Supported add-ons:
- extra poster/key visual
- extra motion cutdown
- dossier rollout extension
- print study / artifact package
- additional format adaptation set
- expedited turnaround
- editable file delivery
- extended usage / paid media license
- on-set or live consultation

Add-ons should attach to an approved base offer.

---

## Red flags / decline cases

Decline or pause when:
- the client refuses to define objective, deadline, or budget range
- the brief requires copying another artist or brand directly
- the project is a clear weak fit and demands generic output
- the client wants full rights transfer without budget support
- the decision-maker is unclear and feedback flow is fragmented
- the deadline requires rush production but the client rejects rush pricing
- the client wants canon language or lore as public-facing strategy without understanding translation
- the client asks for unlimited revisions

Use direct language.
Do not over-explain the decline.

## Commercial translation guardrails

The commercial front-end may use pressure from the system.
It must not force literal Paradise Lobby behavior into every project.

Always preserve:
- strong direction
- typography discipline
- sequence logic
- image-world coherence
- tactile proof when useful

Do not force by default:
- case numbering
- barcode language
- residue logic
- denial language
- internal doctrine words

This keeps commerce aligned with the system without collapsing into cosplay.

## Minimum quote record

For every issued quote, record:
- project / client name
- date
- fit level
- chosen offer
- deliverables
- formats
- timeline
- revision rounds
- usage summary
- add-ons
- exclusions
- quote status
- owner

No quote is production-ready unless this record exists.
